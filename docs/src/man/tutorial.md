## Constructing Models

One of the strengths of tensor network methods is that, by working directly with state vectors and matrix representations of time-evolution operators, they do not require deriving specific equations for different models.
Provided one can express the generator of the time evolution as a sum of terms amenable to a tensor network representation with respect to some tensor product of local Hilbert spaces, the methods in described in this thesis can be used.
That is *not* to say that the tensor network will necessarily capture the dynamics of the quantum state accurrately, or even allow for stable evolution, but the handle can nevertheless be turned.

Models are generated by appending objects that are subtypes of `AbstractTerm` to an instance of the `Model` type.
Each element in the iterable `Model` represents a operator appearing in a Suzuki-Trotter decomposition, represented by the `TrotterLayer` type.
Multiple terms can appear in the same `TrotterLayer` indicating that these terms are *not* trotterised over, i.e. the sum of these terms are exponentiated.

As an example, consider the spin-``\frac{1}{2}`` Heisenberg model with dissipation and dephasing. This model can be constructing using the following code:
```julia
function heisenberg(;Jx = 0.0, Jy = 0.0, Jz = 0.0, γ = 1.0)
    # Get the Pauli matrices
    X,Y,Z = PAULI 

    # Initialise an instance of the model object
    model = Model{Liouvillian}()

    push!(model, Jx * LocalOp(X,X))
    push!(model, Jy * LocalOp(Y,Y))
    push!(model, Jz * LocalOp(Z,Z))

    # Add the dissipator
    push!(model, Dissipator(γ * Z, 1 / 2 * (X - im * Y))

    return model
end
```
To demonstrate this in more detail, it is useful to work directly in the Julia REPL.
First, define some useful variables:
```@repl
X,Y,Z = PAULI; # Get the Pauli matrices
XX = LocalOp(X,X);
YY = LocalOp(Y,Y);
ZZ = LocalOp(Z,Z);
```
Each of `XX`, `YY` and `ZZ` are objects in the following type hierarchy:
```@repl
typeof(XX) <: LocalOp{2} <: AbstractSingleTerm <: AbstractTerm
```
Adding terms together results in `Hamiltonian` objects:
```@repl
H = XX + YY + ZZ;
H isa Hamiltonian
```
and adding a `Dissipator` to a `Hamiltonian` constructs a `Liouvillian` object:
```@repl
L = H + Dissipator(Z, 0.5 * (X - im * Y));
L isa Liouvillian
```
A `Dissipator` can be constructed with any number of Lindblad jump operators as positional arguments to the constructor.
Optionally, a `Model` object can be constructed which allows greater control over the Suzuki-Trotter decomposition of the time-evolution operator.
Layers can be added to a `Model` both at time of construction
and later using `push!`.
```@repl
model = Model(XX, YY);
push!(model, ZZ);
length(model)
```
If the second argument to `push!` is a layer of purely one-local terms (including terms of type `Dissipator` as TimeEvolutionPEPO.jl currently supports on-site dissipation only), then this layer is distributed evenly amongst all *existing* layers in `model`, multiplied by the appropriate prefector.
If this is undesired, then either add the one-local terms to the model first, or explicitly construct a `Hamiltonian` or `Liouvillian` containing these local terms before pushing this to `model`.
```@repl
model = Model(XX, YY);
push!(model, LocalOp(X));
length(model) # No additional layer has been added
push!(model, zero(Hamiltonian) + LocalOp(X));
length(model)
push!(model, Hamiltonian(LocalOp(X)));
length(model)
```
Note, if one wishes to eventually `push!` a dissipator to an object of type `Model`, then it is best to explicitly specify the type parameter at construction as pushing a `Dissipator` or `Liouvillian` onto a `Model{Hamiltonian}` will result in an error.

## Computing Observables

To calculate expectation values of observables, one must first construct a reduced density matrix from the tensor network.
To do this, a boundary algorithm (and associated boundary bond dimension) must be chosen to compute the partial trace of the environment around those lattice sites to be left untraced.
Such an object is represented by the `DensityMatrix` struct.
A `DensityMatrix` can the be used to compute reduced density matrices.
```julia
function magnetisation(pepo::PEPO; alg = CTMRG(bonddim = 16))
    dm = DensityMatrix(pepo, alg)
    rdm = partialtrace(dm, (1,1))

    M = expval(rdm, PAULI[3])

    return X
end
```
In practice it is useful to save the `DensityMatrix` object rather than running the boundary renormalization every time one wishes to compute a local observable.
The correlation length of a state can be directly accessed directly from the `DensityMatrix` object without first needing to compute a partial trace:
```@repl
pepo = PEPO((0,0,-1), ℂ^2, ℂ^4);
dm = DensityMatrix(pepo, VUMPS(bonddim = 16))
correlationlength(dm)
```
It is also possible to compute arbitrary ``n``-point observables be computing reduced density matrices over multiple sites:
```julia
function cx13(dm::DensityMatrix)
    X = PAULI[1]
    id = one(X)

    rdm13 = partialtrace(dm, (1,1), (3,1)) # specified sites do not have to be adjacent
    cx13 = expval(rdm13, X, X) - expval(rdm13, kron(X, id)) * expval(rdm13, kron(id, X))

    return cx13
end
```
## Running Simulation

Simulations must first be initialised:
```julia
function newsim(model)
    # Set initial state to a product state of spins aligned along the x-axis
    ρ = (1,0,0)

    # Use a two-by-two unit cell.
    s = fill(ℂ^2,2,2)

    # Set the bond dimension equal to 4
    D = ℂ^4

    # Initialise using the TEBD (with default options)
    method = TEBD()

    # Construct the tensor network
    state = PEPO(ρ, s, D)

    sim = Simulation(state, model, method; timestep=0.01)

    return sim
end
```
We can then run the simulation be calling `simulate!`.
```julia
function runsim!(sim)
    # Execute 100 timesteps without a callback function.
    simulate!(sim; numsteps = 100, maxshots = 0)

    M = Float64[]

    # Execute an additional 100 timesteps, computing the magnetisation each time.
    simulate!(sim; numsteps = 100, maxshots = 100) do sim
        push!(M, quantumstate(sim) |> magnetisation)
        return nothing
    end

    return M
end
```
Information pertaining to a given `Simulation` object can be obtained by calling
```@repl
simulationinfo(sim)
```
which can also be accessed in the callback function.
